# collaro.app — the Collaro website

The public website for the **Collaro** mobile app (a dog‑services marketplace), served at
<https://collaro.app>: the marketing homepage, the support page, and the public legal pages
(Terms of Service, Privacy Policy, Account Deletion, Deleting Your Data — English and Hebrew).

Plain HTML/CSS/JS, no framework, no dependencies. A tiny node script renders `src/` into `docs/`,
which GitHub Pages publishes.

## Layout

```
src/
  layout.html            the ONE page chrome: <head> metadata, header/nav, footer
  site.json              site-wide config: URL, contact email, App Store / Google Play URLs
  strings/en.json        every UI + marketing string (English)
  strings/he.json        Hebrew (same keys; the 404 page is English-only by design)
  pages/                 page templates ({{key}} placeholders): index, support, 404
  legal/                 the legal documents, one file per language:
                           terms-of-service.*.html, privacy-policy.*.html  ← GENERATED by the app, never edit
                           account-deletion.*.html, data-deletion.*.html   ← hand-maintained here
  partials/              reusable snippets ({{>name}})
  icons/                 inline SVG icons ({{icon:name}})
scripts/
  build.mjs              src/ → docs/ (also writes docs/sitemap.xml)
  serve.mjs              local preview of docs/ with GitHub Pages' URL rules
  legal-redirects.mjs    cutover helper for the old legal.collaro.app repo (run only when told to)
  optimize-screenshots.ps1  store artwork → web-sized docs/assets/img/screenshots/*.jpg + the OG card
docs/                    THE PUBLISHED SITE (GitHub Pages: branch main, folder /docs)
  <page>/index.html      generated — do not edit by hand (one directory per page = its URL;
  <page>/he/index.html     the Hebrew copy sits in he/ below it; the home page is index.html)
  *.he.html, sitemap.xml generated — redirect stubs for the old flat URLs, and the sitemap
  404.html               generated — the one page that must stay a root file
  assets/css, js, img    hand-managed static files (store artwork under assets/img/screenshots/)
  CNAME, .nojekyll, robots.txt
```

## Working on the site

```
npm run build   # render src/ → docs/
npm run serve   # preview at http://localhost:8080 (behaves like GitHub Pages: /support/, 404 page)
npm run check   # fail if docs/ is out of date (run before committing)
```

Preview with `npm run serve` — every link and asset path is root-relative (`/assets/…`,
`/privacy-policy/`), so the pages do not work opened straight from the file system.
Commit `src/` **and** `docs/` together.

- **Copy** lives in `src/strings/en.json`. The pages only reference keys, so wording changes never
  touch markup. An unknown key fails the build.
- **Languages**: a page template is rendered in every language whose strings file has its
  namespace (`home`, `support`, `notFound`), so `/he/` and `/support/he/` come from
  `he.json` automatically, with `dir="rtl"`, the Hebrew store artwork and a language switch in the
  header of every page that has a twin. A third language = one more `strings/<lang>.json`.
- **Store links**: set `appStoreUrl` / `playStoreUrl` in `src/site.json`. While they are empty the
  buttons render as "Coming soon" (no dead links) and the build prints a reminder.
- **Screenshots**: the store listing artwork lives in `docs/assets/img/screenshots/` as web-sized
  JPEGs named `<name>.<lang>.jpg` (English and Hebrew). Regenerate them from the originals with
  `scripts/optimize-screenshots.ps1` — see [that folder's README](docs/assets/img/screenshots/README.md).
  Captions/alt text are in `strings/en.json` under `home.screens`.
- **Design tokens** (colours, radius, shadows, type) at the top of `docs/assets/css/site.css`
  mirror the app's light theme (`frontend/src/theme/*` in the app repo). The site is light-only
  and does not follow the OS colour scheme. Change tokens there, not per component.

## URLs

| Page | English | Hebrew |
| --- | --- | --- |
| Home | `https://collaro.app/` | `https://collaro.app/he/` |
| Support | `https://collaro.app/support/` | `https://collaro.app/support/he/` |
| Terms of Service | `https://collaro.app/terms-of-service/` | `https://collaro.app/terms-of-service/he/` |
| Privacy Policy | `https://collaro.app/privacy-policy/` | `https://collaro.app/privacy-policy/he/` |
| Account Deletion | `https://collaro.app/account-deletion/` | `https://collaro.app/account-deletion/he/` |
| Deleting Your Data | `https://collaro.app/data-deletion/` | `https://collaro.app/data-deletion/he/` |

Every page is a directory with an `index.html`, so the URL is the directory: no `.html`, no
language suffix (the slugs are the ones the old `legal.collaro.app` site used). GitHub Pages
serves a directory only at its trailing-slash form and redirects `/support` → `/support/` itself,
so the extensionless links in the app and the store listings keep working.

The old flat addresses are kept alive too:

- `/<page>.he.html` (e.g. `/terms-of-service.he.html`) is a generated redirect stub — meta
  refresh + canonical — to `/<page>/he/`.
- `/<page>.html` (e.g. `/terms-of-service.html`) cannot have a stub: GitHub Pages would then
  serve that file for `/<page>` instead of redirecting into `/<page>/`. Those links land on the
  404 page, which forwards them to the clean URL with a line of JavaScript. (They were never
  published anywhere — the app, the stores and the sitemap always used the extensionless form.)

## The legal pages

**Terms of Service and Privacy Policy are generated from the app** — the text lives in the app
repo (`frontend/src/legal/*.json`) and is published from there:

```
cd <app repo>/frontend && npm run legal:html            # writes src/legal/*.html here and runs the build
cd <app repo>/frontend && npm run legal:html -- --check # verifies the published copies are in sync
```

Never edit `src/legal/terms-of-service.*` or `privacy-policy.*` by hand — the next run overwrites
them. The two deletion pages are maintained here; keep their wording aligned with the Terms and
Privacy Policy. Every legal document is a chrome‑less fragment (front matter + `<h1>` + sections);
the site layout adds the header (with the language switch), footer and metadata around it.

## Deploying (GitHub Pages)

1. Push the repo to GitHub (`collaro-app/collaro.app-website`).
2. **Settings → Pages → Build and deployment**: *Deploy from a branch* → `main` / `/docs`.
3. **Custom domain**: `collaro.app` (matches `docs/CNAME`); tick *Enforce HTTPS* once the DNS
   check passes.
4. DNS for `collaro.app`:
   - `A` records for the apex → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`,
     `185.199.111.153`
   - `AAAA` records for the apex → `2606:50c0:8000::153`, `2606:50c0:8001::153`,
     `2606:50c0:8002::153`, `2606:50c0:8003::153`
   - `CNAME www` → `collaro-app.github.io` (GitHub then redirects `www` → apex)

## Retiring legal.collaro.app (cutover checklist)

Only after every page above has been verified live on `collaro.app`:

1. Update the store listings (privacy policy URL, support URL, Google Play "delete account" URL)
   to the `collaro.app` URLs.
2. Turn the old pages into redirects so existing links keep working:
   `node scripts/legal-redirects.mjs --out ../Collaro-legal`, then commit and push in that repo.
   Keep its GitHub Pages + `CNAME` enabled while the redirects should live.
3. Later, when the old links no longer matter: disable Pages on `collaro.app-legal` and drop the
   `legal` DNS record.
